# 没有第二次运行：RSI 会停在前沿预训练吗？

SII & Xinxu AI

## 摘要

预训练是每一个基础模型的起点；若把递归自我改进（recursive self-improvement, RSI）带到这里，人工智能就能改进那个创造人工智能的过程，并可能改变整个行业构建基础模型的方式。然而，公开的 RSI 工作迄今只针对后训练：它从一个已有的基座模型出发，运行耗费 GPU 时的试验，并返回可验证的分数。预训练上的 RSI 以高出数个数量级的成本把这三个条件全部打破：一次运行要在数月内消耗数十万 GPU 时，并且无法重复；其目标——后训练余量——无法从任何单一分数直接读出；必须改进的不是一个模型，而是整套生产与组织系统，从数据流水线和训练基础设施，一直到运行它们的团队。据我们所知，我们是世界上第一个把 RSI 应用于一次从头开始的完整前沿预训练运行，并对其作详细报告的工作。RSI 并不会停在前沿预训练，但它会改变形态：既然没有任何端到端循环能够在一次不可重复的运行上闭合，我们就把*预训练循环*分解为若干能够闭合的更小循环，每一个都修补完整运行所破坏的某一步。

结果是 801-30B-A3B-Base<sup>†</sup>，一个由新组建的团队在三个月内、于 11.8T token 上从零训练得到的 30B-A3B 混合专家（MoE）模型。我们把它作为*基座*模型发布：完整的后训练留待后续发布，此处报告的轻量监督微调（SFT；6B token，无强化学习）只用于探测后训练余量。作为基座模型，801-30B-A3B 优于 Qwen3-30B-A3B 与 Nemotron-3.5-Lightning-30B-A3B，仅落后于更大的 Qwen3.5-35B-A3B，并且在相同 SFT 下保持这一位置；仅凭轻量 SFT，它在四个智能体基准上相对经过完整后训练的模型取得了最高平均分，其中包括 Qwen3.6-35B-A3B。后训练 RSI 从本工作结束之处开始：它以一个强基座模型为前提，而这正是预训练必须产出的东西。因此，把 RSI 带入预训练，作用于此后每一个阶段所赖以建立的基础。我们将开源 801-30B-A3B-Base 以及轻量 SFT 数据——一套用于评估基座模型后训练余量的现成资源——地址为 <https://github.com/GAIR-NLP/801-30B>。

† 我们将该模型称为 801（读作 eight-oh-one），名称来自构建它所在的教室。

## 1 引言

递归自我改进（RSI）是指一个系统把自己的经验与反馈转化为持久的改变，从而提升自身能力。它已经迅速从构想走向实践。智能体现在神经网络架构 (Xu et al., 2026b)、GPU 内核 (Yu et al., 2026; Fu et al., 2026a)、智能体套件（harness）(Xia et al., 2026) 上运行循环 $\textit{propose}\rightarrow\textit{run}\rightarrow\textit{measure}\rightarrow\textit{update}$，而最接近模型构建的，是在后训练本身上运行这一循环 (NeoHorse Team et al., 2026; Rank et al., 2026; Huang et al., 2026)。这些循环在触及预训练时，是经由小规模代理来进行的：在小模型上验证的数据策展与数据选择策略 (Mi et al., 2026; Xu et al., 2026c; Meng et al., 2026)，或者以分钟计的单 GPU 训练运行 (Karpathy, 2026; Guo et al., 2026)。这些设定共享三个条件：它们从一个已有的基座模型或一个玩具规模的模型出发，每次试验的成本是 GPU 时或更低，并且每次都返回一个可验证的分数。预训练是每一个基础模型的起点，而这三个条件它一个都不满足。把 RSI 带到那里，将使人工智能能够改进那个创造人工智能的过程本身；然而据我们所知，还没有任何公开工作在一次完整的前沿预训练运行上尝试过这一点。

预训练上的 RSI 并不是后训练上的 RSI 的一个更难实例，而是另一种体制（表 1）。第一，它破坏了“运行”。单次运行要在数月里消耗数十万 GPU 时，而大多数项目只负担得起一次全长运行。把单一原因隔离开的消融实验成本在 GPU 周这一量级，因此大多数假设从未得到端到端检验。第二，它破坏了“度量”。预训练的目标不是今天的最高分，而是留给后训练的余量。一次追逐指标的运行可能悄然透支后训练，例如过早把监督微调（SFT）数据退火混入，或者压低输出多样性，从而牺牲强化学习（RL）日后所依赖的余量 (Yue et al., 2025)。这样的目标无法从任何单一分数读出；即便一个界定清晰的基准也会被自我改进循环过拟合 (Xia et al., 2026)，如此弥散的目标，被钻空子的方式远多于被真正达成的方式。第三，必须改进的不是一个模型，而是一套生产系统以及运行它的组织。在训练哪怕一个 token 之前，数据就必须先被构建出来：在我们这次运行中，六条流水线、超过 30 个处理阶段，把原始网页、文档和代码转化成了 1,053 个数据子集。训练栈在超过 130 个基础设施代码版本和 106 个超参数字段中演化。这些产物的背后是一个组织：数据、基础设施、训练和评测团队各自持有证据的不同部分，而最难的问题落在各团队之间。例如，一次负载均衡异常浮现在训练指标里，却追溯到一处基础设施改动与优化器设置的相互作用（第 3 节）；没有任何单一团队能够独自把这个循环闭合。因此，改进预训练，就是改进这个组织如何分工、如何共享证据，以及如何记住它已经学到的东西。后训练 RSI 从这个系统结束的地方开始：它预设一个强基座模型，而这正是该系统必须生产出来的东西。

| 方面 | 后训练中的 RSI | 前沿预训练中的 RSI（本文） |
| --- | --- | --- |
| 起点 | 一个已有的基座模型 | 随机初始化 |
| 每次试验的成本 | GPU 时（例如 10 个 H100 时 (Rank et al., 2026)） | 一次运行需数十万 GPU 时 |
| 全长试验次数 | 数十至数百次 | 一次 |
| 度量处的信号 | 可验证的任务分数 | 后训练余量，无法从任何单一分数读出 |
| 数据 | 固定的数据集或环境 | 由原始来源建成：6 条流水线、$>$30 个阶段、1,053 个子集、10.5T 不重复 token |
| 基础设施 | 一段训练脚本 | $>$130 个代码版本、106 个超参数字段 |
| 改进的对象 | 一个模型或一套套件 | 生产系统以及运行它的组织 |
| 循环中的主体 | 一个智能体或一名研究人员 | 数据、基础设施、训练与评测团队及其智能体 |

小规模代理和缩放定律看似提供了一个快速循环，但廉价的循环回答不了每一个昂贵的问题。表面上微不足道的拟合选择会改变拟合出的指数 (Besiroglu et al., 2024; Weng, 2026)，拟合尺度上的细小差异会在万亿 token 尺度上被放大，而一连串代理运行所构成的阶梯假定规模是唯一在变化的东西 (Weng, 2026)。一旦一个问题把架构、配方、基础设施和多源数据配比耦合在一起，为了把它定下来所需的代理研究，就会变得和它本欲降低风险的那次运行一样昂贵。因此，我们用两次试点运行来暴露并消除问题，而不是用来外推分数。

如果端到端循环无法重跑，智能体又在何处确立自己的位置？这次运行留下了庞大的上下文：内部指标、超参数变更、数据配比编辑、基础设施差异，以及对每一个中间检查点的数十次评测，其数量远超任何团队能够读完的程度，更谈不上记住。这一体制下典型的浪费不是一次糟糕的实验，而是重新调查数周之前已经解决的问题，因为没有人把症状与它所归属的那一类原因联系起来。瓶颈因此从算力转向机构记忆：尝试过什么、什么失败了以及为什么失败、哪些信号同时出现。智能体确立自己位置的方式，是在没有人会读完的证据上完成回忆与归因；并且，在凡是能够建立快速信号的地方，由它们自己把工作做完：构建数据流水线组件、爬取网页，并以任何团队都无法手工覆盖的广度生成智能体训练数据。

我们对标题中那个问题的回答是：RSI 不会停在前沿预训练，但它会改变形态。既然没有任何端到端循环能够在一次不可重复的运行上闭合，我们就把预训练分解为若干能够闭合的更小循环，每一个都修补完整运行所破坏的某一步。*调试循环*把“运行”重新安置到可以廉价重跑的基础设施与数据栈上；*余量循环*为整次运行修补“度量”；*经验到指标循环*则在原本没有度量的地方建立度量。一套共享的*上下文基础设施*充当这个组织的记忆：它跨团队整合证据，并保存阴性结果及其原因，更新步骤在这里持续存在，递归也在这里发生（图 2）。

**图 2：** 标准 RSI 循环（$\textit{propose}\rightarrow\textit{run}\rightarrow\textit{measure}\rightarrow\textit{update}$）在前沿预训练中无法闭合：一次运行耗时数月且不能重复，而今天的分数也反映不出一个检查点留给后训练的余量。我们提出三类循环，并实例化为六个可操作的循环。调试循环包括基础设施调试循环和数据调试循环，它们把内部指标异常与输出异常追溯到其原因。余量循环被实例化为配方循环，用余量度量来引导整个预训练过程。经验到指标循环包括分类器开发循环、站点发现循环和爬取覆盖循环，把基于经验的判断转化为可测量的反馈。全部六个循环共享一套上下文基础设施，在规模上跨团队整合证据。

我们在训练 801-30B-A3B 的过程中建立了这些循环。801-30B-A3B 是一个 30B-A3B 混合专家（MoE）(Shazeer et al., 2017) 模型，由一个新组建的团队在三个月内于 11.8T token 上从零训练而成。据我们所知，这是把 RSI 应用于一次完整前沿预训练运行的第一份公开记述。我们的贡献如下：

- *（a）调试循环（第 3 节）。* 一个*基础设施调试循环*和一个*数据调试循环*，分别由内部指标异常和输出异常驱动。在两次试点（分别停在 1T 与 3T token）和主运行中，智能体定位了横跨基础设施、数据与配方的原因，从与优化器状态相互作用的负载均衡惩罚，到低多样性的合成数据，并在大约一个月内解决了五项跨栈诊断。这些修复连同数据与配方的修订，在对齐的 1T token 预算上，把 22 个基准（附录 B）上的平均分从 47.78（初始试点）提高到 51.96（修订试点），再提高到 56.83（主运行）。

- *（b）一个余量循环（第 4 节）。* 因为基座分数并不保持后训练排序，我们按检查点在适配之后*值多少*来评判它们，使用 tiny-SFT、一条学习禀赋曲线，以及对能力上限的跨协议最大值估计。这些度量把基座评测中表面上的停滞与适配之后持续的增益区分开来。

- *（c）经验到指标循环（第 5 节）。* 分类器开发、站点发现与爬取覆盖：智能体把曾经凭感觉做出的判断，变成有记录、可定量评估的工作流。我们以此从零建立了六条数据流水线。

- *（d）预训练尺度上的智能体数据（第 6 节）。* 智能体从消耗训练跨越到生产训练：在九套套件上铺开的 22 万个可执行拉取请求，产生了超过 100B token 的已验证智能体轨迹（智能体 token 合计 134B），用于预训练的长上下文阶段。

##### 我们发布什么，以及如何比较

我们把 801-30B-A3B-Base 作为*基座*模型发布。完整的后训练留待后续发布；此处报告的轻量 SFT（6B token，无 RL）只用于探测后训练余量。因此我们在三个层次上进行比较，从对我们最公平的一层到对我们最不利的一层（第 8 节）。（1）*基座对基座*：801-30B-A3B 优于 Qwen3-30B-A3B (Yang et al., 2025a) 与 Nemotron-3.5-Lightning-30B-A3B (NVIDIA et al., 2026)，仅落后于更大的 Qwen3.5-35B-A3B (Qwen Team, 2026a)。（2）*相同 SFT*：当每一个基座模型都在同一份 SFT 数据上微调时，它保持这一位置。（3）*轻量 SFT 对完整后训练*：即便如此，在我们所比较的、经过完整后训练的模型中，它在四个智能体基准上取得了最高平均分，其中包括 Qwen3.6-35B-A3B (Qwen Team, 2026b)。第三项比较把数十亿 SFT token 与厂商完整的后训练流水线对照；我们把它作为余量的参照点来报告，而不是同等条件的对比。我们将开源 801-30B-A3B-Base 以及轻量 SFT 数据——一套用于评估基座模型后训练余量的现成资源——地址为 <https://github.com/GAIR-NLP/801-30B>。

## 2 使 RSI 适应前沿预训练

递归自我改进（RSI）是这样一种想法：一个系统把自己的经验与反馈转化为持久的改变，从而提升自身能力，并在最强的形式上，连改进过程本身也一并改进。它背后的引擎是一个闭合循环，AlphaEvolve (Novikov et al., 2025) 与 ASI-Evolve (Xu et al., 2026c) 是其例证。我们把该循环写作 $\textit{propose}\rightarrow\textit{run}\rightarrow\textit{measure}\rightarrow\textit{update}$，并在本报告中把它用作 RSI 的操作性定义。在本报告中，正在改进的系统是预训练项目本身，包括其中的智能体、研究人员与基础设施，而不是正在被训练的那个模型。

四个步骤值得精确界定。*提出*形成一个候选改动或假设，这一角色相当于生成—批评—修订方案中的生成器 (Madaan et al., 2023)，以及提议者—求解者自对弈中的提议者 (Zhao et al., 2025)。*运行*把该候选付诸实现以产生证据，方式是训练、铺开或执行它。*度量*用一个代替人类判断或期望目标的信号给证据打分。Chen et al. (2026) 把候选信号排列成一个验证层级，强的一端是形式化验证器，弱的一端是模型内在的自我评估。*更新*把结果折回为持久的改变，保留得分更高的部分并丢弃其余；在递归情形下，它还会修订产生该改变的循环机制本身。正是这种持久性使循环成为递归，而不是一次性搜索。

有两个前提决定这个循环是否真能改进任何东西。第一是廉价、可重复的迭代：只有当一次试验便宜到“运行”与“更新”能够循环许多次时，增益才会复合累积。第二是度量处有一个与真实目标对齐的可靠信号。没有外部信号，就没有可靠的改进；信号若弱或未对齐，循环会经由自我确认误差、模型坍缩与多样性坍缩 (Shumailov et al., 2024)，或者锁定在一个提法良好但错误的目标上而退化 (Chen et al., 2026)。

如第 1 节所论证的，前沿预训练把两个前提都打破了：全长运行无法重复，而它的真实目标——后训练余量——过于弥散，无法充当可信的度量。而且，必须改进的系统是一个组织，而不是一个模型。因此，标准的端到端循环并不能迁移到这一体制。我们保留这个循环，但改变它闭合的位置。

##### 三类循环

我们并不把预训练做成一个由分数驱动的单一循环，而是在它周围闭合三类更小的循环，共六个具体实例（图 2）。表 2 展示了每一类如何实例化这四个步骤。

- *调试循环*把“运行”重新安置到基础设施与数据流水线栈上，诊断可以在那里廉价重跑。它们由异常驱动，而不是由一个待最大化的分数驱动：度量问的是异常是否消失，每一个被排除的原因都作为阴性结果记录下来。*基础设施调试循环*把异常的内部指标追溯到基础设施代码或训练配方设置，*数据调试循环*把异常的输出模式追溯到特定的数据源或处理阶段（第 3 节）。

- *余量循环*为整次运行修补“度量”。它的信号是后训练余量，经由 tiny-SFT、学习禀赋和跨协议最大值评测来估计，而不是从基座模型分数直接读出。它被实例化为*配方循环*，用这些度量把配方从分别停在 1T 与 3T token 的两次试点修订到主预训练，并在主运行内部监测进展（第 4 节）。因为它的“运行”就是那次昂贵的运行本身，每个项目里它只闭合少数几次。

- *经验到指标循环*在原本没有度量的地方建立度量。构建数据流水线组件、获取网页数据等步骤，以往都是手工调的；我们给每一步一个显式评测，例如任务专用评测集或 SEO 页面数估计，从而使各次修订可以相互比较。这一类被实例化为*分类器开发循环*、*站点发现循环*和*爬取覆盖循环*（第 5 节）。

##### 上下文基础设施

这些循环作用在预训练的不同部分，但全都需要跨越团队的证据：一处异常可能把模型的输出连接到数周之前做出的数据处理决定，余量度量必须与配方和检查点历史放在一起读，数据工作流必须保留每一次修订背后的评测。我们建立了一套*上下文基础设施*来整合这些证据（内部指标，例如逐层损失、逐模块梯度范数和专家负载均衡统计，以及超参数变更、数据配比编辑、基础设施差异和检查点评测）。这些证据由分别掌管数据、基础设施、训练与评测栈的智能体和研究人员产生，规模大到任何团队都无法在没有辅助的情况下读完（表 1）。它记录的不只是尝试过什么，还有什么失败了以及为什么失败，从而使阴性结果成为持久知识。更新步骤在这里持续，我们这些循环中的递归也在这里发生：每一个新提议都从先前迭代已经排除的内容出发，智能体把力气指向下一个尚未解决的瓶颈，而不是重新发现旧的瓶颈。

##### 从试点到主预训练

这些循环合在一起，支撑了两次试点与主预训练之间对数据和训练配方的修订（图 4）。初始试点停在 1T token，修订试点停在 3T，主运行使用了约 11.8T token；图中主预训练展示到 Stage1-1 的 7T。这些修订把调试、余量评估和经过定量评测的数据工作流汇到一起。

## 3 调试循环

本节展示我们在第 2 节引入的、运行在上下文基础设施上的两个调试循环。（1）*基础设施调试循环*把异常的内部指标追溯到基础设施代码或训练配方设置。（2）*数据调试循环*把异常的输出模式追溯到特定的数据源或处理阶段（图 5；表 2 把这两个循环都映射到 RSI 的四个步骤）。与通过反复训练并比较候选模型来提升性能的常规 RSI 做法不同，这些循环在单次预训练运行内部运作。它们并不重启训练来评估新的候选模型，而是随着训练推进持续识别、归因并消除问题，从而改进正在进行的这次运行本身。我们以这些循环产出的五项跨栈诊断作结（表 3）。

### 3.1 基础设施调试循环

基础设施调试循环以内部训练指标为起点，在预训练期间识别并解决异常。通过上下文基础设施把这些信号与基础设施代码和训练配方配置联系起来，智能体可以把意外的模型行为追溯到其底层原因，提出有针对性的修复，并在正在进行的训练运行中验证其效果。我们通过两次试点运行中观察到的异常来说明这一过程，遵循四步：检测、归因、修复与验证。

**检测。** 在两次试点运行期间，经由上下文基础设施扫描内部指标的智能体，在 MoE 负载均衡指标中识别出两种对照鲜明的模式（图 6）。在初始试点中，较强的均衡惩罚下，总体 MaxVio 与逐层 MaxVio (Wang et al., 2024a) 都下降到很低的水平，引发对潜在过度均衡的担忧。修订试点呈现出不同的模式：第 15 层与第 18 层出现大幅且持续的 MaxVio 违反，而总体值仍落在典型范围内。这一差异表明，仅监测总体值会掩盖严重的层特异失衡。最后一层第 48 层也偏高，但我们并不单凭这一点就把它当作失败的证据，因为它的功能与输出空间紧密相关。这两种模式合在一起说明，监测 MoE 负载均衡必须同时查看总体趋势和层特异偏离。

**归因。** 为了识别这些异常的来源，智能体使用上下文基础设施，把指标轨迹与基础设施代码提交和优化器配置关联起来。通过检索超过 130 个基础设施代码版本和 106 个超参数字段，它们把原因收窄到负载均衡惩罚实现的一处改动，以及该改动与某些参数组的优化器状态更新之间的相互作用。这一过程建立了一条归因链：从训练停滞到内部指标异常，再从这些异常到具体的基础设施与配置改动。智能体并不把异常指标当作孤立症状，而是跨越训练栈追溯它们，以识别底层原因。

**修复。** 基于这一诊断，我们首先修订了试点配置：把负载均衡 (Fedus et al., 2022) 系数从 $10^{-2}$ 降到 $10^{-4}$，把学习率从 $2.7\times 10^{-3}$ 降到 $5\times 10^{-4}$，并把路由器参数的优化器从 Muon (Jordan et al., 2024; Liu et al., 2025) 切换为 AdamW (Loshchilov and Hutter, 2019)。这些设置被带入主预训练，并另有两处调整：在全局批次上而不是按微批次计算负载均衡损失 (Qiu et al., 2025)，以及把归一化参数与偏置参数排除在权重衰减之外。因为若干因素一起改变，这一比较并不能分离任何单项调整的贡献。这些改动合在一起，构成了主预训练所使用的修订训练配置。

最后，上下文基础设施使这些诊断经验能够跨迭代持续存在。因为先前的诊断及其支撑证据被保存了下来，类似异常的再次出现可以被预先料到，而不必从头重新发现。这使我们能够以早期的 MaxVio 信号作为进一步调查的依据，而不必等到下游评测增益已经走平。

### 3.2 数据调试循环

**图 8：** 诊断模型输出中的不良模式。*上：* 三种有代表性的输出模式：一处凭证泄露并附带逐字重复的配置块；跳入固定的 “Does this sentence make sense?” 问答模板；以及一串近乎相同的应用题自我增殖链。*下：* 把每一种模式追溯到数据流水线缺陷的八步循环。智能体在规模上负责检测、追溯与检查，人类设定分诊优先级并批准修复。

在两次试点期间，我们持续监测已训练模型的输出行为。智能体在模型对问候和常见问题的回答中识别出反复出现的模式，这些模式指示训练数据存在重复、低多样性或清洗不足。它们提取这些异常模式，并在规模上于数据流水线中搜索匹配的签名。

**异常模式。** 图 8 展示了模型输出中观察到的三种有代表性的模式。（1）第一，*凭证泄露与重复*：给定提示 `deepseek`，模型会发出一段形似 API 密钥的秘密，随后是同一代理配置块的反复拷贝，一直持续到生成长度上限。（2）第二，*跳入固定问答模板*：当给定一个关于晚餐推荐的自然请求时，模型没有回答这个问题，而是切换到固定的 “Does this sentence make sense?”（这句话是否有意义？）多项选择模板，并着手求解这个它自己发明出来的任务。（3）第三，*自我增殖式重复*：仅给定标记 **New Example:**，模型就会生成一串无界的、近乎相同的除法应用题，每一道都遵循同一个四步解题骨架。

**自动化诊断过程。** 图 8 的下半部分说明智能体如何把这些异常模式追溯到具体的数据流水线缺陷。这八步过程可以组织为三个阶段。（1）第一阶段是*检测与模式提取*。智能体在模型生成的样本或评测结果中识别异常，并对相应案例分类。基于所识别的模式，智能体编写检测器，并在全部 1,053 个数据子集上做大规模匹配，以找出可能含有相应异常的子集。（2）第二阶段是*归因与定位*。候选数据子集被识别出来之后，由人类确定调查优先级。智能体随后把这些子集追溯到它们的数据流水线（共六条），并检查这些流水线上超过 30 个处理阶段所产生的中间数据，最终定位到造成异常的具体数据源与处理阶段。（3）最后阶段是*解决与验证*。一旦异常来源被识别，智能体就对数据或流水线提出修复。由人类决定是否批准其执行。获批的修复被应用到相应的处理阶段，随后重新评测模型以验证其有效性；被拒绝的提议则退回修订。

在整个过程中，智能体负责大规模异常检测、数据追溯和逐阶段检查，而人类保留对两个关键决策点的控制：调查优先级和修复批准。这种分工使大规模调查变得系统而可行，超出了仅靠人工检查所能合理完成的范围。

**根因归因与修复。** 经由这一过程，三种异常模式被追溯到三处不同的数据流水线缺陷。（1）第一，凭证泄露与重复这一案例被追溯到代码语料中清洗不足的配置文件。这些文件含有敏感信息和重复的配置内容，它们进入了训练数据，并随后在模型生成中浮现。我们通过修复相应的数据处理阶段、去除这类清洗不足的内容来处理该问题。（2）第二，固定问答模板这一案例被追溯到一份开源问答语料的某个子集中对合成数据过滤不足。该子集含有大量 “Does this sentence make sense?” 问题。我们在相应阶段加强了合成数据过滤，以减少训练数据中这类固定模板样例的存在。（3）最后，自我增殖这一案例被追溯到一条合成数据流水线，其提示设计缺乏足够的多样性，导致生成的样例高度相似。我们修订了相应的提示设计，以提高合成数据的多样性。对全部三个案例，我们都修改了相应的数据流水线阶段，并在应用修复之后重新评测模型，以验证其有效性。

### 3.3 累积诊断

上面描述的两个调试循环说明，智能体如何识别模型行为中的异常，并把它们追溯到基础设施、训练配方和数据流水线中的底层问题。然而，这些只是贯穿训练过程、诊断并解决问题的更广泛努力中的代表性例子。

在两次试点和主预训练中，我们用同一方法系统调查训练系统不同部分的问题。其中许多问题无法归因到单一组件。诊断它们需要把来自内部指标、基础设施代码、训练配置和数据流水线的证据连接起来，并追溯它们之间的相互作用。表 3 总结了经由这一过程识别并解决的五项跨栈问题，涵盖负载均衡、优化器配置、数据质量、权重衰减和数据加载。这些发现表明，在上下文基础设施的支持下，智能体能够识别并解决横跨训练系统多个部分的问题。

**表 3：** 在两次试点与主预训练中，借助上下文基础设施解决的五项跨栈诊断。

| 方面 | 发现 | 修复 |
| --- | --- | --- |
| 负载均衡 | 专家负载要么在所有层上过度均衡，要么在少数个别层上严重失衡（图 6）。 | 采用全局批次负载均衡 (Qiu et al., 2025)，从而放宽按微批次的约束，并允许专家专门化。 |

这些诊断的价值并不止于修复本身，完成它们所需的时间也体现了上下文基础设施的价值。以我们的经验，若没有这样的基础设施，诊断这一类问题可能要花费数月。在智能体的支持下，并凭借把证据连接到整个训练栈的能力，我们在大约一个月内完成了全部五项诊断，大幅减少了识别并追溯这些问题所需的人工投入。

更重要的是，这些诊断的价值延伸到眼前的修复之外。上下文基础设施保存每一次调查中的观察、尝试过的修复和阴性结果，使后续迭代能够建立在先前发现之上，而不必从零开始。因此，每一次调查不仅贡献于改进正在进行的训练运行，也贡献于一份可以在未来迭代中复用的、不断增长的知识。两个调试循环合在一起，把个别的解题努力变成一个持续改进的累积过程，具体的数据改进与训练配方改进被带入图 4 所示的相继迭代之中。

## 4 余量循环

预训练的目标不是把今天的分数最大化，而是为后训练留下最大的余量。度量这一余量，可以为余量循环提供信号。我们首先描述三种互补的度量（第 4.1 节），然后展示它们揭示了基座评测所没有揭示的内容（第 4.1 节），最后说明配方循环如何使用它们（第 4.2 节）。

### 4.1 度量后训练余量

我们用三种度量来评估后训练余量：Tiny-SFT、学习禀赋，以及跨协议最大值评测。它们合在一起捕捉一个模型潜力的三个方面：有限后训练之后的性能、从额外数据中学习的效率，以及它在评测协议下能够展示的能力。

**图 9：** Tiny-SFT 的数据构成与验证。*左：* 6.33B token 混合的 token 构成。数学、科学 (Xu et al., 2026a) 与代码 (Ahmad et al., 2025) 各贡献约 2.00B token（31.6%），指令遵循 (Pyatkin et al., 2025) 贡献 0.331B token（5.2%）。*右：* Qwen3-30B-A3B 与其基座模型（Qwen3-30B-A3B-Base）在一个 epoch 的 Tiny-SFT 之后的对比。分数为 13 个基准上的百分比；微调后的模型在其中 10 个上更高。这一验证支持把 Tiny-SFT 用作监测模型在有限后训练之后性能的代理。

**图 10：** 基座评测中表面上的停滞可以与 SFT 之后仍在改善的性能并存。（a）预训练过程中基座模型的直接 Overall_Avg；红框标出（b）与（c）所考察的检查点区间。（b）与（c）中的每一个点，都是对（a）中某个检查点独立施加同一 SFT 流程之后的 SFT AVG13。（b）Stage1-1，步 123,000–210,000（4.1T–7T token）：尽管基座趋势近乎平坦，SFT 之后的分数仍提高 1.49 分。（c）Stage1-3，步 243,000–345,000（8.1T–11.5T token）：基座分数在一个平台附近波动，而 SFT 之后的分数提高 2.39 分。

**Tiny-SFT。** 仅有基座模型评测，并不能完全捕捉一个模型在后训练之后的潜力。因此，我们对每一个被评测的预训练检查点施加一小份 SFT 预算，并直接测量它在为后训练模型设计的基准上的性能。所得分数近似该检查点在一个有代表性的后训练阶段之后会如何表现，从而对其下游潜力给出更现实的度量。SFT 语料跨越多个任务类别，以近似实际后训练工作流的多样性（图 9）。我们指出，SFT 没有用多个随机种子重复，因此相邻检查点之间的细小差异应谨慎解读。在我们的实验中，Tiny-SFT 帮助我们识别出两种从基座模型评测本身并不容易看出的有趣模式：

**图 11：** 基座与 SFT 之后的检查点排序不可互换。*左：* 同一批检查点的基座 Overall_Avg 与 SFT AVG13。*右：* 全部成对检查点，在每一组内按基座名次排序，并给出对应的 SFT 名次。第 1 名为最优，并列取平均名次，$\rho$ 表示在每一组内根据所报告分数计算的斯皮尔曼相关。基座分数与 SFT 分数使用不同的基准套件。

> （1）虚假停滞。我们观察到，基座模型分数可以看起来进入平台期，而模型在 SFT 之后仍继续改善。图 10 展示了两个区间：基座模型的平均分在一个近平台附近波动，而 SFT 之后的平均分继续提高。在 Stage1-1，从步 123,000 到 210,000（4.1T–7T token），基座模型平均分保持在 61 附近，而两个 epoch 的 SFT 之后的平均分从 65.34 提高到 66.83。在 Stage1-3，从步 243,000 到 345,000（8.1T–11.5T token），基座模型平均分停留在 64–66 左右，而一个 epoch 的 SFT 之后的平均分从 70.54 上升到 72.93。需要指出的是，基座模型分数与 SFT 之后的分数是在不同的基准集合上计算的。因此我们比较的是它们在各自评测设定内部的趋势，而不是它们的绝对值。这些结果表明，若只依赖基座模型评测，可能导致过早决定停止训练，或对训练配方做出不必要的改动。
>
> （2）排序不一致。我们还发现，检查点的相对排序在 SFT 之后可以改变，与它们在基座模型评测下的排序相比有所不同。为考察这一差异，我们把 23 个预训练检查点与其可用的 SFT 结果配对，并把它们在附录 B 所列 22 个公开与内部基准上的基座模型平均分，与 SFT 之后的平均分进行比较（图 11）。由于训练早期的检查点指令遵循能力较弱，我们使用同一份 Tiny-SFT 数据，但在不同训练阶段分配不同的 SFT 预算。具体而言，我们分别计算了 13 个经过两个 SFT epoch 评测的 Stage1-1 检查点，以及 10 个经过一个 epoch 评测的 Stage1-2/Stage1-3 检查点的名次。相应的斯皮尔曼秩相关为 0.796 与 0.438。这些排序正相关，在 Stage1-1 中尤其如此，但它们对检查点余量给出的并不是同一种评估。例如，在 Stage1-1 这一组内，步 159,000 在基座模型评测下排第 1，SFT 之后排第 3；而步 210,000 从第 6 升到第 1。在这两个检查点之间，基座模型平均分从 61.41 降到 60.76，而 SFT 之后的平均分从 66.22 升到 66.83。这些结果表明，仅凭基座模型分数，并不能完全捕捉各检查点在后训练潜力上的差异。

**图 12：** 学习禀赋的一个示意性图示。带空心标记的细线是 SFT 检查点上的原始分数，每一条直线是它们对式 (1) 的最小二乘拟合：截距 $b$ 是第一个检查点 $N_{0}$ 处的分数，斜率 $k$ 是后训练数据每增加十倍所带来的增益。学习禀赋高的模型起点最低，却以比基线少大约 $15\times$ 的数据达到目标分数 $s^{*}$（式 (2)）。高起点、平坦的模型只在所绘制预算的末端才达到该分数。

**学习禀赋。** 一个模型的初始性能并不必然反映它能以多高的效率从额外的后训练数据中学习。因此我们度量它的*学习禀赋*，它刻画的是：随着后训练数据预算增加，一个模型以多高的效率改善。

为了度量学习禀赋，我们选择一个特定领域或任务族，并用同一份领域专用的 SFT 数据微调不同的基座模型。我们在训练全程评测一串中间检查点，以追踪每个模型在看到更多数据时性能如何变化。这使我们能够拟合一条学习曲线，并度量该模型从额外数据中学习的效率。对大多数模型而言，分数近似随事后训练数据预算的对数而线性增长。因此，我们为每个基座模型 $m$ 拟合一条对数线性学习曲线（图 12）：

$$s_{m}(N)=b_{m}+k_{m}\log_{10}\frac{N}{N_{0}}, \tag{1}$$

其中 $s_{m}(N)$ 是经过 $N$ 个单位后训练数据之后的下游分数（实践中为固定批量大小下的 SFT 步），$N_{0}$ 是第一个被评估的 SFT 检查点的数据预算。截距 $b_{m}$ 是该首个检查点上的分数，代表模型在该领域的初始表现。斜率 $k_{m}$ 度量后训练数据每增加十倍时的分数增益，刻画模型从额外数据中学习的效率。我们通过对全部 SFT 检查点做普通最小二乘来估计这两个参数，排除未经调优的基座模型。

单独任何一个参数都无法刻画模型的学习资质。初始分数高但学习曲线平缓的模型起步很强，但从额外数据中获益很少。相比之下，初始分数较低但学习曲线更陡的模型，随着数据预算增加，最终可能超过前者。因此我们把两个参数放在一起考虑，并估计模型 $m$ 达到目标分数 $s^{*}$ 所需的后训练数据量：

$$N_{m}^{*}(s^{*})=N_{0}\cdot 10^{(s^{*}-b_{m})/k_{m}}, \tag{2}$$

然后，我们把这一数据需求与基线模型的数据需求相比较，用比值 $N^{*}_{\text{base}}/N^{*}_{m}$ 来度量数据节省。比值越大，表示该模型达到相同目标性能所需的后训练数据越少。

在本工作中，我们用学习资质比较不同模型，而不是比较同一次训练运行内部的不同检查点。如第 8 节所示，初始分数较低但学习资质更高的模型，在经过充分微调之后，最终可以超过初始分数更高的模型。把这一度量用于单次训练运行内部的检查点选择，是未来工作的一个自然方向。

**跨协议取最大评估。** 模型的评测分数并不总是充分反映其已经获得的能力，因为这些能力被展现到何种程度，可以取决于评测协议。同一基准在困惑度评分、少样本提示和零样本提示下，可能给出非常不同的分数（图 13(a)；协议定义见附录 C）。此外，这些协议的相对表现会随预训练检查点而变化，如图 13(b) 中的 HumanEval 所示。

因此，单一评测协议可能低估模型的能力。为了得到更完整的图景，我们在所有可用协议下评估每个检查点，并对每个基准取最高分。我们的目标是度量模型能够展现的能力，而不是它适应某一种特定评测格式的程度。跨协议取最大值，可以更完整地估计模型的能力上限。对于第 8 节中的跨模型比较，我们遵循该节所规定的评测协议。

（a）801-30B-A3B Base 在不同评测协议下、跨基准的分数。同一基准可以因协议不同而给出不同分数，说明单一评测设定可能捕捉不到模型已经获得的能力。

（b）预训练全程中，HumanEval 在不同评测协议下的分数。分数以及协议的相对排序都会随检查点变化。因此，我们在每个检查点上对可用协议取逐点最大，以更完整地度量模型已展现的能力。

### 4.2 配方循环

*配方循环*把后训练余量测量带入预训练过程，用它们作为反馈，以评估训练进展、指导配方调整，并为后续迭代提供信息。两次先导运行分别在 1T 与 3T token 处停止，随后的主预训练运行构成这一循环中的迭代序列（图 4）。

在整个过程中，我们用余量测量来追踪模型的后训练潜力如何随训练阶段演变，并把结果反馈到预训练配方中。我们并不只关注当前的基座模型分数，而是同时考虑后训练性能、学习效率，以及模型在不同评测协议下能够展现的能力。这有助于我们判断预训练是否仍在积累有用能力，以及当前配方是否需要进一步调整。

基于此前调试所识别的问题，我们在开发训练数据的同时，继续改进基础设施与训练配置。具体而言，主预训练引入了新的 QA 数据，并修订了网页、代码、数学、书籍与论文的比例和采样权重。

核心思想是：预训练进展不应只由当前的基座模型分数来判断，还要看模型是否继续积累那些可以通过后训练进一步发展的能力。即便基座模型评测看似进入平台期，只要后训练余量仍在增长，预训练就可能仍在取得有意义的进展。

## 5 经验到指标循环

预训练中的许多数据处理决策传统上依赖专家经验，例如如何清洗和过滤数据，以及如何判断某种处理策略是否有效。我们把这些由经验驱动的任务，转变为带有显式评价指标的标准化工作流。这样，智能体就能分析错误、修订方法、比较备选方案，并通过反复迭代提升其表现。

我们称之为*经验到指标循环*，并将其应用于三项任务：分类器开发、站点发现，以及爬取覆盖优化。三者遵循同一原则：把人类经验转化为可度量的任务，让智能体执行并改进这项工作，再用评测结果指导下一轮迭代。

### 5.1 分类器开发循环

图 14：数据分类器的迭代开发。*左*：人类定义分类任务（1）；一个强模型抽样数据并标注评测集（2）；智能体分析案例并调优标注提示（3）；强模型使用该提示标注训练数据（4）；从这些标签蒸馏出紧凑分类器（5）并加以评估（6）。该组件可以部署为调优后的提示（方案 A）或蒸馏模型（方案 B）。*右*：广告意图、计算主题与临床健康主题三类分类器在三次迭代（v1–v3）上的准确率与 F1。

关于第一个问题，此前关于*数据达尔文主义*的工作提供了一个框架。它引入十级分类体系（L0–L9），用以组织数据处理操作，从数据获取和格式规范化，到过滤、模型驱动的精炼以及合成（Qin et al., 2026a）。沿用其在 daVinci-LLM（Qin et al., 2026b）中的用法，我们用这一框架指导流水线设计。例如，OCR 属于格式规范化（L1），基于规则与基于模型的过滤对应 L2–L3，用于清洗或修复内容的精炼属于 L4。这一分类体系帮助我们在选择模型、提示或实现之前，先界定每个组件应当做什么。

DataEvolve 探讨一个互补的问题：数据策管策略如何通过反复评测与诊断反馈得到改进（Mi et al., 2026）。受这一思路启发，我们通过共享的评测工作流来开发分类器、过滤器、OCR 模型与重写器。数据达尔文主义指导处理操作的选择，而评测循环帮助判断某一具体实现是否很好地完成了其预定任务。图 14 以分类器为例说明这一过程，共三个阶段（图中为六步）。

*步骤 1：定义任务并构建评测集。* 研究者规定分类器应当做什么。随后，一个强模型标注有代表性的样本，以建立参考评测集。这确立了质量标准，并为比较提示、模型与处理规则提供共同基础。由于参考标签来自强模型，评测度量的是与该模型的一致性，而不是与人类判断的一致性。

*步骤 2：分析错误并改进组件。* 智能体并行分析数百到数千个样例，识别反复出现的错误模式，并利用这些发现修订提示、比较模型或调整处理规则。每一次修订都对照同一任务定义和评测集进行评估，从而使我们能够判断这些改动是否真正提升了性能。

*步骤 3：验证并部署。* 修订后的组件在部署前经过评估。对于分类器，其结果可以用作调优后的标注提示，也可以用强模型标注的训练数据蒸馏成更小的模型。蒸馏得到的分类器经过评估，循环继续进行修订以提升其性能。评测能够发现回退：在图 14 中，三个分类器都在 v2 时损失了准确率，随后在 v3 回升。

在不到三个月的时间里，我们构建了六条数据流水线，智能体贡献了 36 项模型选择决策，以及提示优化与分类器构建。

### 5.2 网页获取：站点发现循环与爬取覆盖循环

图 15：结构感知的网页数据获取。一项人类需求为带有两个循环的智能体驱动流水线提供种子。循环 1（站点发现）通过网页的链接结构扩展并核验相关站点。循环 2（爬取覆盖）将每个已确认站点爬取到由其 SEO 页面估计所告知的覆盖目标。链接、搜索索引与 robots 指令被当作结构化信号加以利用，而不是被丢弃。

公开网页是预训练数据的主要来源，但系统地找到高质量来源，并尽可能完整地采集其内容，仍然具有挑战。一种常见做法从种子文档出发，用分类器检索相关页面，并识别这些页面集中出现的域名（Shao et al., 2024）。然而仍有两个问题：我们如何持续发现更多有价值的站点，以及如何判断是否已从每个站点采集到足够的数据？

我们用两个相互连接的、由智能体驱动的循环来回答这些问题：*站点发现循环*寻找高质量数据来源，*爬取覆盖循环*则旨在尽可能完整地采集其内容。两者都使用搜索引擎优化（SEO）工具提供的信息；这些工具给出相关站点信息以及已索引页面数的估计，作为指导发现和度量爬取覆盖的信号。图 15 展示了该流水线。

**循环 1：站点发现循环。** 站点发现的目标，是把一小集高质量种子站点扩展为更广泛的相关数据来源集合。我们使用 SEO 工具，通过网页的链接结构识别与种子相关的候选站点。随后，智能体访问每个候选站点，检查其相关性与质量，并把通过核验的站点加入种子集，供下一轮发现使用。我们用每一轮的*已验证产出*来度量其有效性，即通过核验的已发现站点数量。每一轮通过核验的站点成为下一轮的种子，使发现能够迭代扩展。当某一轮不再产生新的合格站点时，过程停止。这就把“下一步该去哪里找”这一基于经验的决策，转变为可度量、可重复的发现过程。

**循环 2：爬取覆盖循环。** 一旦识别出有价值的站点，下一项任务就是尽可能完整地采集其内容。对于每个已确认站点，智能体编写并运行爬虫，然后把已抓取页面数与 SEO 工具提供的页面数估计相比较。我们用*覆盖率*作为评价指标，定义为已抓取页面数除以估计的页面总数：

$$\text{覆盖率}=\frac{\text{已抓取页面}}{\text{估计页面}}$$

尽管 SEO 页面计数是估计值，它们仍为评估爬取覆盖提供了定量参照。智能体把已抓取数量与这一估计相比较，调查潜在缺口，修订爬虫，并再次运行以测量由此得到的覆盖。这样，爬取就成为由可度量覆盖驱动的迭代过程，而不是对站点何时已被充分爬取的非正式判断。

##### 闭合这些循环。

站点发现循环与爬取覆盖循环针对网页数据获取中两个互补的挑战：到哪里去找更多有价值的数据来源，以及如何尽可能完整地采集其内容。它们与分类器开发循环一起，遵循同一原则：把由经验驱动的任务转变为带有显式评价指标的工作流，使智能体能够执行工作、评估结果，并通过反复迭代改进方法。具体而言，分类器开发使用特定于任务的评测分数，站点发现使用每一轮的已验证产出，网页爬取使用覆盖率。关键在于，给那些曾经依赖专家判断的任务以明确的目标与评估程序。智能体随后可以利用反馈来确定一项任务完成得如何，以及下一步应当改进什么。这就把基于经验的决策转变为系统化、可重复的过程，使预训练一次一个组件地变得更加科学。

## 6 将智能体数据扩展进预训练

智能体数据由智能体在求解具有可验证结果的真实世界任务时生成的轨迹组成，已在后训练中被证明有效（Pan et al., 2025; Yang et al., 2025b）。真实世界的软件开发提供了这类任务的丰富来源，也为预训练带来新的机会。我们的目标是把这一数据来源扩展到数千亿 token，同时保持任务多样性与数据质量。

然而，达到这一规模所需要的，不止于常规的数据处理流水线。真实世界的软件任务多样，涉及复杂的任务构造、执行环境、测试，以及跨智能体 harness 的集成。我们认为，*大规模使用智能体是将智能体数据扩展进预训练的必要条件*。主要瓶颈不是生成少量高质量样例，而是系统地把多样的真实世界软件开发活动转化为可执行、可验证且可扩展的训练数据。

图 16：智能体数据流水线概览。关键组件是验证门（Validation gates）：只有当任务通过策略、执行与语义检查，并且同一评测在初始代码上失败、在参考实现上通过时，才接纳该任务；随后将其净化为 Docker/OCI 镜像，该镜像保留外部评测，但剥离参考补丁与原始历史。被拒绝的任务连同证据和修复提示返回（虚线路径）。

### 6.1 为何智能体数据需要智能体

**复杂的任务构造与验证。** 真实的软件开发为智能体数据提供了丰富的任务来源。近期工作探索了若干方向：通过自动化的环境与评测脚本构造，使开发任务可执行（Fu et al., 2026b）；在中期训练轨迹中保留开发上下文与执行反馈（Zeng et al., 2026）；以及把相关 PR 连接成更长的任务链（Jiang et al., 2026）。

要把这一数据来源扩展到预训练，就必须处理真实世界开发活动的全部多样性。这既包括任务定义清晰且测试维护良好的 PR（Jimenez et al., 2024; Pan et al., 2025; Badertdinov et al., 2025），也包括描述不完整、需求隐含，或把多个工作项捆绑在一起的 PR。对于每个 PR，流水线必须构造三个彼此一致的组件：可复现的执行环境、说明智能体应当做什么的指令，以及核验任务要求是否被满足的测试与评测脚本。

这些组件必须一起开发。例如，仓库的 CI 可能注入构造环境中被遗漏的环境变量，导致评测因与代码变更无关的原因而失败。另一种情况是，测试可能要求特定名称的函数，而指令只描述期望行为，从而使一个有效实现被拒绝。单个 PR 也可能捆绑多个工作项，使指令、环境与测试的任务边界不一致。

因此，任务构造所涉及的，不止于简单地从 PR 中抽取任务描述。环境、指令与评测必须就任务要求什么达成一致。智能体需要检查仓库上下文，识别这些组件之间的不一致，并相应地修订它们。在规模化时，这一过程必须处理仓库特定约定与开发实践的长尾。

图 17：多 harness rollout 层。统一适配器中的一次 `launch(harness, prompt, infer_cfg)` 调用驱动全部九个已集成 harness，它们之间使用三种 API 协议（Anthropic Messages（Anthropic, 2026）、OpenAI Responses（OpenAI, 2026b）与 OpenAI Chat Completions（OpenAI, 2026a））。Bifrost 网关（Maxim AI, 2025）将这三种协议规范化到同一个 LLM 服务后端，并集中注入推理设置（上下文长度、最大输出、温度）。

**多 harness 集成与维护。** 即便在构造出任务之后，要大规模生成多样的轨迹，仍需要在执行期间支持多个 harness。我们把九个 harness 集成进智能体数据流水线：Claude Code（Anthropic, 2025）、Codex（OpenAI, 2025）、Pi-Agent（Earendil Works, 2025）、OpenCode（Anomaly, 2025）、OpenHands（Wang et al., 2025）、Droid（Factory AI, 2025）、Hermes（Nous Research, 2025）、OpenClaw（OpenClaw contributors, 2026）与 SWE-agent（Yang et al., 2024）。每个 harness 都有自己的接口、依赖与失败模式。即便是同一模型，在不同 harness 上的行为也可能不同。此外，harness 更新与新插件会引入进一步的配置变更。

因此，模型、harness 与版本的组合需要持续的集成与维护。我们使用统一适配器在不同 harness 上启动 rollout，并由智能体帮助诊断执行失败、修订集成并验证更新后的配置。随着这些组合增长和变化，人工维护变得不可持续。因此，要维持大规模轨迹生成，智能体是必要的。

**轨迹质量控制与反作弊。** 反作弊对于产出高质量智能体数据至关重要。模型可以通过许多方式利用评测捷径（Zhong et al., 2025; jacobkahn, 2025），而要在规模上检测这类行为，智能体必不可少。在数据合成流水线中，智能体必须区分两类问题：*作弊（hacks）*，即模型绕过任务而不是真正求解它；以及*合成缺陷*，即执行环境、测试或任务指令本身存在缺陷。这一区分尤其困难，因为模型的作弊行为可以掩盖任务中的缺陷，使一个无效任务看起来可解。为此，智能体扫描执行轨迹以寻找异常行为，例如访问 Git 仓库与日志、下载相关软件包、搜索代码提交，或使用绕过实际任务逻辑的 shell 命令。可疑案例被标记出来，供人工复核或重新合成（表 4）。

因此，要大规模产出智能体数据，不仅需要使任务可执行，还需要验证模型确实在求解它们，并且由此得到的轨迹是可信的。

### 6.2 为预训练扩展智能体数据

通过上述任务构造、多 harness 执行与质量控制过程，我们建立了一条可大规模产出智能体数据的流水线。

图 18：智能体数据流水线的漏斗图。260K 条原始 PR 被过滤为 220K 个可执行任务。每个任务在 9 个 harness 下 rollout，得到约 2M 条轨迹。核验之后剩余 1.1M 条轨迹，合计超过 100B 训练 token（平均每条轨迹约 91K token）。任务与轨迹绘制在不同的尺度上。

我们所收集的原始拉取请求中，超过 84% 被成功转换为可执行任务。对于这些 PR，我们构造了执行环境，抽取了任务要求，并合成了相应测试（图 18）。然后，我们把由此得到的 220K 个可执行 PR 在九个 harness 上 rollout。轨迹由中小规模的开放权重模型生成，包括 DeepSeek-Flash 与 GPT-OSS。经过分层过滤，我们得到 1.1M 条达到预训练质量标准的智能体轨迹，合计超过 100B token，平均每条轨迹约 91K token。再加上来自其他多样来源的轨迹，可用于预训练的智能体数据总量达到 **134B** token。重要的是，这些轨迹并不仅仅是后训练的辅助成分，而是*预训练的一等数据源*。

由智能体驱动的数据流水线代表训练数据生产方式的转变。随着模型能力增强，它们可以求解更难的任务，并生成更丰富的训练信号。与此同时，随着 harness 与工具演变，智能体可以适配底层的集成层。除了增加更多 harness，每个 harness 内部的插件生态也在迅速增长，进一步扩大了必须支持的配置空间。

我们预期，由智能体驱动的数据流水线将成为未来前沿预训练运行中，高质量、多样且可验证的训练数据的日益重要的来源。

### 7.1 注意力均衡的数据采样

把长序列混入训练数据所造成的吞吐量下降，会远远超过其占比所暗示的程度。理论上，期望训练时间应当是花费在长样本与短样本上的时间按比例加权之和。实践中，仅加入 10% 的长样本就可能使训练速度减半。

借助上下文基础设施，智能体把这一意外放缓追溯到计算气泡，其成因是数据并行（DP）各 rank 之间不均衡的注意力工作量。在同步的数据并行训练中，注意力工作量更重的 rank 成为掉队者，使其他 rank 在同步点上空闲等待。对于打包序列，这种不均衡尤为严重，因为注意力代价取决于各文档长度，而不是 token 总数。我们将每个包的代价估计为下式，其中 $m_{p}$ 统计文档片段数，$\ell_{p,j}$ 是片段 $j$ 的长度。

$$\widehat{C}(p)=\sum_{j=1}^{m_{p}}\ell_{p,j}^{2}, \tag{3}$$

为缓解这种不均衡，数据加载器在有界窗口内按估计的注意力代价对包进行排序，并把代价相近的包组成全局微批次。当每个 DP rank 接收多个包时，我们进一步按代价从高到低，把包分配给仍有剩余容量且当前负载最低的 rank（图 22a）。

排序窗口限制样本重排的幅度。更大的窗口改善负载均衡（图 22b），但文档长度可能与数据来源和难度相关。因此，激进的排序可能使每一步的配比产生偏差，并在长上下文训练早期显著增大损失波动。我们使用有限的排序窗口，缓冲区大约为分布式 world size 的两倍，以在计算效率与样本多样性之间取得平衡。

为评估这一策略，我们在 256 块 GPU 上比较了两次配置相匹配的 256K 上下文预训练运行。我们在 256 块 GPU 上评估所提出的数据加载器，上下文并行度为 4（CP=4），从而得到 64 个数据并行（DP）副本。每个 DP 副本一个包，排序窗口为八个全局微批次时，我们的方法取得 $2.26\times$ 的吞吐量提升（从 1,126 提高到 2,543 TGS）。平滑后的训练损失走势相近（图 23）。由于该调度改变了全局样本顺序，我们另行评估了最终模型质量；有无该调度时的基准差异仍处于运行之间的波动范围内。

## 8 评测

我们通过互补的比较来评估 801-30B-A3B：基座模型性能、监督微调（SFT）之后的通用能力，以及相对已后训练模型的智能体能力。基座模型比较直接评估预训练检查点，而 Base+SFT 比较考察适配之后的通用能力。智能体比较进一步在 SWE-bench Verified、SWE-bench Pro、CyberGym 与 KernelBench 上评估性能。这些设定分开呈现，以便把直接的基座模型评测与适配之后的下游性能区分开来。

鉴于当前的资源与时间约束，我们把初始评测与优化集中在本节所报告的设定上，尤其侧重智能体任务。我们计划在未来工作中扩大任务覆盖，并提供更全面的评测支持。

### 8.4 学习潜能

图 25：801-30B-A3B 与 Qwen3-30B-A3B 在 SWE-bench Pro（左）和 BFCL Full（右）上的学习潜能。空心标记是相继各个 SFT 检查点上的分数；浅色线是式 (1) 的最小二乘拟合，图例中的 $k$ 为其斜率，即 SFT 步数每增加十倍所带来的分数增益。

##### 在 BFCL 上起点更低、学习更快

在第一个检查点（第 55 步），801-30B-A3B 在 BFCL Full 上的分数为 31.32，低于 Qwen3-30B-A3B 的 40.04。然而，它的斜率是 SFT 步数每增加十倍获得 8.62 分，对比之下 Qwen3-30B-A3B 为 3.33，大约陡 $2.6\times$。从第 697 步起，它在每一个两者共有的检查点上都处于领先，并在第 3,485 步以 48.65 对 46.26 结束。这正是促使提出学习潜能的情形：一个起点更低但学习更快的检查点，一旦微调运行得足够久，就会超越起点更高的检查点。

##### 在 SWE-bench Pro 上起点更高且学习更快

在 SWE-bench Pro 上，801-30B-A3B 从第一个检查点起便领先，第 30 步为 26.95 对 0，并且学习更快，斜率为 9.15 对 5.03。Qwen3-30B-A3B 在前三个检查点（直到第 120 步）一直保持为 0，并在第 1,922 步达到 8.76，而此时 801-30B-A3B 达到 43.37。在这里，截距与斜率指向同一方向，因此随着微调继续，差距随之扩大，而不是收窄。

## 9 结论

我们试图回答一个当前 RSI 的成功仍留待解答的问题：在前沿预训练中，智能体能够做些什么？在那里，$\textit{propose}\rightarrow\textit{run}\rightarrow\textit{measure}\rightarrow\textit{update}$ 循环无法闭合，因为这次运行不可重复，而目标也不是一个分数。我们的答案来自在三个月内构建 801-30B-A3B 的过程，那就是围绕三类循环来组织改进。调试循环由基础设施调试循环和数据调试循环组成，它们把不寻常的内部指标和输出模式与其原因连接起来。五项跨栈诊断在大约一个月内得到解决，它们出自这些调查。提升空间循环被实例化为配方循环，借助微型 SFT、学习潜能以及跨协议取最大评测来指导配方修订，并监测训练进展。经验到指标循环由分类器开发循环、站点发现循环和爬取覆盖循环组成，把基于经验的判断转化为智能体可用于改进数据工作流的反馈。它们全都共享一套上下文基础设施，用以在规模上跨团队整合证据，并保留负面结果及其原因。

由此得到的模型证明，这一机制能够在规模上运转。801-30B-A3B 在 30B MoE 规模的开源基座模型中，于直接基座评测和匹配 SFT 比较两方面都达到最先进水平；并且在一个 6B token 的 SFT 阶段之后，它在智能体任务上接近同规模档次中经过完整后训练的前沿。但我们把模型视为副产品，把这份记述视为贡献。我们的经验表明，RSI 不必在前沿预训练处止步。它采取另一种形式：循环消除异常，提升空间的测量指导训练，定量反馈改进数据工作流。共享的上下文使证据与教训得以跨团队、跨迭代积累。也许不会有第二次运行，但我们已有的这一次，仍然能够从它自身的进展中学习。
